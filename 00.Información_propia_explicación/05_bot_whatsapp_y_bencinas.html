Arquitectura Multicanal: Un Solo Cerebro, Dos Canales

Novedad de hoy: el bot ahora responde por WhatsApp (Twilio) y por Telegram (@Mi_cartera_descuentos_Bot), con la misma logica. El "cerebro" (procesar el mensaje, avanzar el flujo, armar la respuesta) es una sola funcion; cada canal es apenas un adaptador delgado que traduce transporte y formato. Sigue sin IA/LLM en ningun canal.

Como se reparte el trabajo

CapaQue hace
Cerebro (compartido)Procesa el texto del usuario, avanza user_flow, arma la respuesta (menu, resultados, link). Una sola funcion para los dos canales.
Adaptador WhatsAppRecibe el POST de Twilio en /webhook, valida (opt-in) la firma X-Twilio-Signature, responde en TwiML XML con markdown WhatsApp.
Adaptador TelegramRecibe el POST de Telegram en /telegram, quita el markdown de WhatsApp (* _) para que no salga literal, responde en JSON via sendMessage de la API de Telegram.

WhatsApp (Twilio)

  • Endpoint: POST /webhook
  • Costo: lo cobra Twilio por mensaje
  • Seguridad: valida X-Twilio-Signature si hay TWILIO_AUTH_TOKEN configurado (opt-in)
  • Formato: markdown WhatsApp (*negrita*, _cursiva_) se renderiza normal
  • Se activa solo si esta configurado Twilio

Telegram (@Mi_cartera_descuentos_Bot)

  • Endpoint: POST /telegram
  • Costo: gratis, Telegram no cobra por mensaje
  • Seguridad: token del bot; el webhook se AUTO-REGISTRA al arrancar el servidor
  • Formato: texto plano — el * y _ se quitan (se verian literales)
  • Se activa solo si existe TELEGRAM_BOT_TOKEN

Cada canal es opt-in independiente: si falta el token de uno, ese canal simplemente no se activa (no rompe el otro ni el resto de la API). El estado de conversacion tambien se separa por canal para no mezclar el flujo de un usuario de WhatsApp con uno de Telegram (detalle en "Estado conversacional", mas abajo).

Calidad y Trazabilidad de los Descuentos de Bencina (2026-08-03)

Regla: un agregador (sitio de terceros) es control de calidad, NUNCA fuente de verdad. Los 31 descuentos de bencina se re-curaron desde la fuente oficial de cada cadena; el agregador solo sirve para detectar inconsistencias.

Guardia de madrugada vigila la trazabilidad

La revision automatica de cada madrugada (~03:00 Chile, revision_madrugada.py, en GitHub Actions) chequea bencinas: si un descuento pierde su campo confianza o vuelve a depender solo del agregador, manda alerta por correo. La trazabilidad se vigila en cada corrida, no se verifica una sola vez. Es parte de una guardia mas amplia de 7 guards que ademas miden contra la fuente los dias y la region de los beneficios, los % absurdos, la frescura de los datos y los nombres genericos (ver el resumen del proyecto).

Detalles Tecnicos

Estado conversacional

user_flow = {}
# Estructura por usuario. La CLAVE se prefija por canal para no mezclar
# el flujo de un usuario de WhatsApp con uno de Telegram:
# {
#   "+56912345678": {              # WhatsApp (numero, sin el prefijo "whatsapp:")
#     "step": "ask_mode" | "ask_dia_rest" | "ask_banco"
#           | "ask_dia_bencina" | "ask_banco_generico",
#     "mode": "restaurantes" | "bencinas" | "cuotas" | "otros",
#     "dia": "lunes",
#     "bancos": ["BCI", "Scotiabank"],
#   },
#   "tg_123456789": { ... },       # Telegram (prefijo "tg_" + chat_id)
# }

Se mantiene en memoria (se pierde si el servidor reinicia). Cada usuario tiene su propio estado, y ese estado se borra apenas el bot entrega el resultado (la proxima vez que escribe, arranca de nuevo desde el menu). "Cuotas" y "Otros beneficios" comparten el mismo paso ask_banco_generico — solo cambia el mode, asi el codigo no se duplica.

Seleccion de bancos

  • El bot muestra una lista numerada de bancos
  • Restaurantes: el usuario puede seleccionar multiples bancos separando numeros con coma: "1,2,4"; tambien acepta "todos"
  • Cuotas sin interes y Otros beneficios: seleccion de UN solo banco (o "todos") — no admiten multi-seleccion
  • Los bancos de Restaurantes seleccionados se pasan como parametros URL multiples: ?banco=BCI&banco=Scotiabank

Generacion del link "Ver todo"

  • Restaurantes es el UNICO flujo que pasa filtros en la URL: /ver?dia=X&banco=Y&banco=Z
  • Bencinas, Cuotas y Otros beneficios linkean a la pagina general, sin parametros: /ver/bencinas, /ver/cuotas, /ver/beneficios
  • Al abrir un link con filtros (Restaurantes), la pagina los aplica automaticamente desde la URL

Sin dependencias externas de IA (en ningun canal)

  • No se usa OpenAI (ni GPT ni embeddings) en el bot, ni por WhatsApp ni por Telegram
  • No se usa Pinecone en el bot
  • Todo el filtrado y formato se hace en Python puro, sobre los 4 datasets locales
  • El endpoint /rag sigue disponible en la API — lo usa el buscador de la web (/ver), no el bot
  • Costo mensual de OpenAI para el bot (WhatsApp + Telegram): $0
